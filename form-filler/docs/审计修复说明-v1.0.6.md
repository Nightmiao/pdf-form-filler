## 一、先看这里：本轮的三个"非代码"变更

### 1.1 GitHub 历史被重写过（重要）

**原因**：推送备份时被 GitHub 拒绝 —— 历史里有超过 100MB 的构建产物：

| 文件 | 大小 |
| --- | --- |
| `form-filler/installer/form-filler.msi` | 117.65 MB |
| `form-filler/installer/msi-info/File/*`（218 个） | 合计约 110 MB |
| `form-filler/build-installer/LMM-Setup/LMM-Setup.pkg` ×3 | 61.26 MB |
| `form-filler/build-win7/狸猫猫表单/*.pkg` ×3 | 55.50 MB |
| `form-filler/installer/staging/*`（390 个，含 24MB DLL） | 合计约 60 MB |

这些文件在更早的提交里被加进来过，虽然后续提交已把它们移出**工作树**，
但它们仍留在**历史**中，因此任何一次推送都会被 pre-receive 钩子拒绝。

**做法**：只重写**尚未推送**的那一段历史（`28adeee..本地尖端`），从索引里移除
上述构建产物目录；远端已有的两个网页端提交（`Create README.md`、`Delete .claude`）
保持原 SHA 不动，最终是一次**快进推送**。

**校验**（这是关键，请复核者相信数据而不是我的描述）：

```
git diff --stat a4907af HEAD   →  无差异
重写前 51 个跟踪文件 / 重写后 51 个跟踪文件
git rev-list --objects master  中已无 >2MB 的 blob
```

即：**源码树与重写前逐字节一致**，只是历史里少了几百 MB 的构建产物。
一个提交（"清理：临时探针与打包中间产物移出版本库"）因为在剔除产物后 diff 变空
而被 `--prune-empty` 丢弃，其内容已被后续提交覆盖，工作树不受影响。

**回滚**：重写前的完整仓库已打包在
`C:\test\pdf-form-filler-before-rewrite.bundle`（329.73 MB，`git bundle verify` 通过），
需要时 `git clone` 该 bundle 即可恢复原历史。

## 四、被推翻的审计结论（重要，避免复核者重复采信）

### 4.1 P0-2"撤销后改属性把撤销结果整体写回" —— 实测不成立

审计认为：撤销后 `_current_field` 仍指向孤儿对象，用户改属性会把撤销前的值写回。
实测（构造合法的 undo 前提，即先 `push_undo` 再旋转）：

```
旋转后模板 rotation = 30.0     撤销后 = 0.0
面板 _current_field is None = True      属性区 isEnabled = False
改完名字后模板 rotation = 0.0  →  撤销没有被反向写回
```

即撤销后属性面板会**清空选择并禁用属性区**，不存在孤儿回写。**未做改动**。
（审计报告里对 `field_panel.py:206-225` 的这一处判断有误；不过"属性面板可能指向
孤儿对象"这个问题在**画布删除字段**路径上确实存在，就是 P1-8，已修。）

### 4.2 `select_field_on_page` 补发信号会无限递归

审计把"该函数不发 `field_selected_sig`"列为幽灵状态。我按建议补发后，
`smoke_test` 直接**栈溢出崩溃**（`0xC00000FD`）：

```
_on_field_focus_requested → panel._on_field_selected_in_list
→ field_focus_requested → canvas.select_field_on_page → field_selected_sig
→ main_window._on_field_selected_in_design → panel.select_field → …
```

即"非空选中不发信号"是**刻意**的，用来断开这个环。已回退改动，并在函数上写明原因。
右面板高亮的同步由 `MainWindow._on_field_focus_requested` 自己负责。

### 4.3 "槽内未捕获异常会 `qFatal` 终止进程" —— 在 PySide2 5.15.2.1 上不成立

审计据此把 D1 描述成"进程终止"。实测（`venv-py38`，PySide2 5.15.2.1）：
异常只打印 traceback，**进程继续运行，退出码 0**。

这条更正其实**提高了** D1 的严重性判断：打包后的 EXE 是 `--windowed` 无控制台，
这段 traceback 无处可去 —— 用户看到的正是"点一下缩略图，画布全白，什么提示都没有"。

## 六、升级/兼容性注意

1. **D2 的语义变化会影响"页面矫正角 ≠ 0 且字段是在旧版本里画的"模板。**
   旧版本在矫正页上画框时，存储的 rect 是"旋转后两个角点"，本版本改为
   "宽高不变、中心回转 + 字段角度取 −矫正角"。新画的框完全正确；**旧数据里
   在非零矫正角页面上画的字段**，其存储 rect 本来就带形状偏差，升级后显示仍会
   偏。建议复核者在真机上用一份这种模板确认影响面，必要时给用户一个
   "把页面矫正角归零后重画该页字段"的提示。
2. 模板/记录 JSON 的**格式未变**（没有增删字段，`checked_by_default` 原本就在），
   `.lmt` 互通。
3. 记录/模板 id 的合法性校验会拒绝含 `../` 等字符的 id。正常情况下 id 是 uuid hex，
   不受影响；只有被人为篡改过的数据才会被拒绝（拒绝方式是"当作不存在"，不报错）。
